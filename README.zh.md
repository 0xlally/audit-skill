# Audit Skill

这是一个面向 agent 的提交前审核 skill，不是漏洞挖掘指南。它用于 agent 或研究员已经产出漏洞候选之后，由一个严格审核器判断该候选是否可提交、是否夸大、证据是否不足、是否重复、是否属于预期行为，或是否是误报。

英文主版本见 [README.md](README.md)。

## 目标

这个 skill 主要用于降低 agent 漏洞报告带来的审核成本：

- 把静态代码可疑点写成真实漏洞。
- 把理论攻击链写成已验证可利用。
- 只看到危险 sink，就声称 High/Critical 影响。
- 为了达到目标严重性而调整 CVSS 向量。
- 忘记检查文档、既有修复、advisory、issue 历史、受支持版本和赏金范围。

理想结果很简单：通过这个 skill 审核的漏洞，应该是保守、可复现、面向维护者、可以提交的报告。

## 工作流

skill 使用八个闸门审核已有候选：

1. 冻结原始声明，区分事实和假设。
2. 标注 `E0` 到 `E4` 证据等级。
3. 验证可达性和安全 barrier。
4. 验证攻击者控制和前置条件。
5. 证明实际机密性、完整性、可用性和 scope 影响。
6. 运行维护者驳回模拟器。
7. 重新计算 CVSS，删除夸大表述。
8. 只有结论可辩护时，才产出提交包。

## 结论类型

- `可提交`：证据充分，报告可以发送。
- `提交前需修改`：问题真实或可信，但报告还需要修改。
- `需要验证`：缺少关键运行时、版本或影响证明。
- `降级`：问题真实，但严重性或影响被夸大。
- `拒绝`：误报、重复、预期行为、范围外或没有安全影响。
